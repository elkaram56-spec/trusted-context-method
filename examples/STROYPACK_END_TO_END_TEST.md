# TCM v1.5 — сквозной контрольный прогон «Стройпак»

**Статус:** документарный тест (design-time), не исполнение в Onto/MCP.  
**Основание:** `docs/ru/method-reference.md`, разделы 6–8.  
**Дата среза кейса:** 2026-05-25.  
**Вопрос:** «Кто отвечает за согласование Договора №1 на 25.05.2026?»  
**Правило:** согласование ≠ подписание; назначение ≠ делегирование.  
**Известный из спецификации факт:** S2 описан как приказ №41 от 02.05.2026 о назначении руководителя ОЗС. Точный locator и первичный документ не предоставлены для данного прогона. Остальные S0–S4 не проверены.

## Маршрут и результаты

| Этап | Проверка | Результат | Обоснование |
| --- | --- | --- | --- |
| FRAME / VBQ | Вопрос, дата и разграничение согласования/подписания сформулированы | REVIEW | Вопрос определён, но утверждение владельцем вопроса не зафиксировано |
| MODEL / MVTC | Типы Contract, Person, Department, Role, Rule, Source, Evidence, Claim; пробел о делегировании | REVIEW | Возможна модель, но утверждённой MVTC нет |
| BUILD / TCBS | READ → PLAN → APPROVE → WRITE → READ BACK → COMPARE | NOT RUN | Нет согласованного плана, журнала записи и фактического read-back; PASS не присваивается |
| GROUND / GCP | S0–S4, версии, locators, scope, действительность | GAP | У S2 нет проверенного locator, исходный Evidence Pack не представлен |
| CONNECT / TCAC | Реальный доступ, permission snapshot, request log, retrieved IDs | NOT RUN | Не выполнялось чтение из Onto/MCP; аутентификация не равна фактическому чтению |
| VERIFY / VRP | Правило «назначение → полномочие» и независимые основания делегирования | GAP | Назначение не доказывает право согласования; нет подтверждения полномочия на дату среза |
| DECIDE / DSP | ACT только при достаточных основаниях и authority | REQUEST EVIDENCE (условный проект) | Требуется документ о полномочии; решение не утверждено уполномоченным человеком |

## Ключевые утверждения

| Claim | Эпистемический статус в рамках доступных материалов | Основание |
| --- | --- | --- |
| S2 описывает назначение руководителя ОЗС | UNKNOWN для первичного факта; описание в спецификации известно | Исходный приказ и точный locator не проверены |
| Назначение само по себе подтверждает полномочие согласования Договора №1 | Не поддерживается | Отсутствует допустимый warrant и доказательство делегирования |
| Конкретное лицо уполномочено согласовать Договор №1 на 25.05.2026 | UNKNOWN | Не представлены применимые правила и подтверждение полномочий |
| Можно разрешить согласование договора сейчас | Не установлено | Не пройдены GROUND, VERIFY, DECIDE |

## Предлагаемый DSP (не утверждённый)

- `decision_status`: `REQUEST EVIDENCE`
- `verification_ref`: проект VRP; итог `GAP`
- `authority`: UNKNOWN — лицо, уполномоченное принять решение, не установлено
- `rationale`: назначение на должность не тождественно делегированию полномочий согласования конкретного договора
- `next_action`: ответственный за кадровые/договорные полномочия (назначается владельцем процесса) → предоставить применимый регламент, приказ/доверенность или матрицу полномочий, действующие на 2026-05-25 → повторить GROUND и VERIFY
- `constraints`: не выдавать `ACT` до проверки полномочия и человеческого утверждения
- `revisit_trigger`: получение проверяемого документа о полномочиях или изменение области/даты вопроса

## Инварианты: документарная проверка

| Инвариант | Итог |
| --- | --- |
| Appointment ≠ Delegation | PASS: вывод не подменён |
| UNKNOWN ≠ FALSE | PASS: отсутствие подтверждения не объявлено доказательством отсутствия полномочий |
| UNKNOWN ≠ STOP | PASS: выбран запрос доказательств, а не безусловная остановка |
| KNOWN ≠ ACT | PASS: даже установленное назначение не даёт права действовать |
| RETRIEVED ≠ GROUNDED ≠ VERIFIED | PASS: непроверенные сведения не объявлены проверенными |
| APPROVE записи контекста ≠ одобрение договора | PASS: полномочия разделены |

**Важно:** PASS здесь означает корректность логики *документарного сценария*, не успешное исполнение Gate в системе.

## Условия перехода к исполнительному тесту

1. Получить оригиналы S0–S4, версии, locators, даты действия и разрешение на использование.
2. Зафиксировать VBQ и MVTC с явным утверждением владельца.
3. Создать согласованный план BUILD и исполнить READ BACK/COMPARE без побочных изменений.
4. Выполнить фактическое чтение контекста и сохранить запросы, разрешения, retrieved IDs.
5. Проверить правило полномочий, конфликты, дату среза и пределы вывода.
6. Утвердить DSP уполномоченным человеком; не разрешать ACT на основании одного назначения.

## Итог

**Design-time safety logic: PASS.**  
**Evidence sufficiency: GAP.**  
**Runtime execution: NOT RUN.**  
**Official seven-Gate end-to-end acceptance: NOT PASSED.**

Тест не подтверждает, что кто-либо конкретный вправе согласовать Договор №1. Отсутствие доказательства полномочия требует `REQUEST EVIDENCE`, а не `ACT`.
