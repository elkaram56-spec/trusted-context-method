Trusted Context Method

An open, evidence-oriented method for constructing, grounding, verifying and governing AI context for decisions and authorized actions.

Seven stages of the method

01 / FRAME · VBQ

Validated Business Question

Frame the decision question, date, scope, acceptance criteria and authority boundary.

Gate: Question, scope, decision criteria and temporal frame are explicit.

02 / MODEL · MVTC

Minimum Viable Trusted Context

Model the smallest sufficient set of entities, relations, rules, claims, evidence needs and unknowns.

Gate: The model is minimal, sufficient and explicit about unknowns.

03 / BUILD · TCBS

Trusted Context Build Snapshot

Implement a reviewed model; record READ → PLAN → APPROVE → WRITE → READ BACK → COMPARE.

Gate: Read-back matches the approved plan without unauthorized side effects.

04 / GROUND · GCP

Grounded Context Package

Link each claim to identifiable source, exact evidence locator and explicit inference rule or warrant.

Gate: Evidence is traceable; gaps and conflicts are disclosed.

05 / CONNECT · TCAC

Trusted Context Access Check

Demonstrate actual authorized retrieval using connector calls, identifiers and permission scopes.

Gate: Retrieval and permissions are demonstrated, not merely configured.

06 / VERIFY · VRP

Verification Result Package

Evaluate claims, evidence, rules, dates, scope, contradictions and unknowns.

Gate: Inferences are justified and limits made explicit.

07 / DECIDE · DSP

Decision & Scope Package

Record ACT / REQUEST EVIDENCE / ESCALATE / STOP with rationale, authority and next owner/action.

Gate: The proposed action is justified and within authority.

Three independent control dimensions

Epistemic status

KNOWN · DERIVED · INFERRED · UNKNOWN · CONFLICTED

Delegation

AUTO · REVIEW · HUMAN

Decision

ACT · REQUEST EVIDENCE · ESCALATE · STOP

KNOWN ≠ ACT · UNKNOWN ≠ FALSE · RETRIEVED ≠ GROUNDED ≠ VERIFIED
