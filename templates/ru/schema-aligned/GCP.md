## G4: критерий PASS/FAIL

**PASS:** Каждый существенный Claim связан с точным Evidence/locator либо явно UNKNOWN.

**FAIL / ограничение:** Не превращать неподтверждённое в KNOWN.

| Контроль | Результат |
| --- | --- |
| Структурная проверка | PASS / FAIL / NOT RUN |
| Семантическая проверка REVIEW/HUMAN | PASS / FAIL / NOT RUN |
| Основание, Evidence / locator | _____ |
| Проверяющий и дата | _____ |
| Расхождения и следующий согласованный шаг | _____ |

**Важно:** заполненность формы не доказывает истинность утверждений, достаточность свидетельств или полномочие действовать. UNKNOWN не заменяется догадкой. В BUILD APPROVE означает согласование записи в контекст, не одобрение бизнес-договора.

## Редакционное пояснение к применению

**Повторяемость G4:** одна строка/экземпляр записи GCP описывает связку `source_id` + `source_version` → `evidence_id` + `locator` → `claim_id` (+ `warrant_id` при необходимости). Для нескольких свидетельств или Claims повторяются записи с теми же нормативными именами полей; нельзя заменять обязательные строки произвольными массивами без изменения контракта §6.4. UNKNOWN фиксируется отдельно как пробел, без фиктивного `evidence_id`. Формат повторяемых записей согласован автором для редакционного применения; исполняемая схема контейнера не утверждалась.

**Редакционная приёмка:** выполнена для RC3 на уровне структуры и полей; проверки Gate по реальному кейсу не выполнялись.

**Авторское решение от 21.10.2026:** соответствующая редакционная конвенция принята. Это не означает прохождения Gate на фактических данных.
